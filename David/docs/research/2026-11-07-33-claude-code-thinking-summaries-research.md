# Claude Code thinking summaries: mechanism, frequency, form, fidelity (2026-11-07)

Tags: [M] measured by me, [S] source (URL), [E] estimate, UNVERIFIED. Quotes scrubbed (a live-looking `sk-ant-oat01-...` OAuth token sits in CheatBench `config.json`; not quoted).

## Headline
1. The "thinking" a plugin sees is never raw. It is (a) a summary from a different model, or (b) empty text plus a signature, or (c) on Claude 5 models, short "progress updates" written for the human watching. [S]
2. Presence is bimodal per session (a settings/entrypoint effect), not a per-model property. [M]
3. Claude 5-era summaries are about 2 sentences and 40 words (about 250 chars), first person, no markdown, and they state a finding then a next action ("I'll ..."). [M]
4. No evidence of softening was found, but no raw/summary matched pairs exist. One Opus 4.6 summary keeps blunt shortcut intent verbatim (CB cb-003307). [M]
5. Recommended: about 25% of training records show summaries (range 10-40%), decided per record, not per step. [E]

## Q1 Mechanism, current
- Docs (thinking page, fetched 2026-11-07) [S https://platform.claude.com/docs/en/build-with-claude/thinking]:
  - "what you see is never the raw chain of thought: the text in a thinking block is a summary".
  - "No `display` setting returns the raw chain of thought."
  - "Summarization is processed by a different model from the one you target... The thinking model does not receive the summarized output."
  - "Summarization preserves the key ideas of Claude's thinking process"; "full intelligence benefits... while preventing misuse".
  - Billing is for full thinking tokens, not summary tokens. "In rare cases where you need access to full thinking output, contact Anthropic sales."
- `thinking.display` values [S, same page]:
  - `summarized`: default on Opus 4.6, Sonnet 4.6 and earlier.
  - `omitted`: empty `thinking` field, signature kept. Default on Fable 5.1, Fable 5, Opus 5.5, Opus 5, Sonnet 5.5, Sonnet 5, Haiku 5.5, Opus 4.8, Opus 4.7, Mythos.
  - `updates` (beta header `thinking-display-updates-2026-08-18`): reasoning blocks empty; progress updates readable.
- Progress updates [S, same page]. Fable 5.1, Mythos 5.1, Opus 5.5, Sonnet 5.5 and Fable 5 can write "a note on what the model just found and what it's about to do next, written for the person watching the agent rather than as reasoning".
  - Each is its own `thinking` block with its own signature, placed right before the `tool_use`.
  - At most one per tool call; "normally a sentence or two"; fewer at higher effort and in long tool chains.
  - May be empty under any display value. Interrupted text is exactly "This part of the response was interrupted before it finished."
  - Sonnet 5.5 has `thinking: {type:"between_tools"}`.
- Opus 4.6 and Sonnet 4.6 and earlier: "the first few lines of thinking output are more verbose"; Mythos summarizes from the first token. [S]
- Safety-redacted content comes back as `redacted_thinking` with an opaque `data` field. It is distinct from `omitted`. [S]
- `stop_details.category: "reasoning_extraction"` refusals exist on Fable 5.1, Opus 5.5, Opus 5, Sonnet 5.5 and Fable 5. [S]
- Manual `budget_tokens` returns 400 on 4.7 and later; adaptive thinking plus `effort` is the control. Opus 5.5, Sonnet 5.5 and Haiku 5.5 default to `medium`, Opus 4.7 to `xhigh`, others to `high`. Adaptive thinking may skip thinking at low effort; interleaving is automatic. [S https://platform.claude.com/docs/en/build-with-claude/extended-thinking, https://code.claude.com/docs/en/model-config]
- Claude Code [S https://code.claude.com/docs/en/model-config, https://code.claude.com/docs/en/changelog]:
  - Thinking can't be turned off on Opus 5.5, Sonnet 5.5, Haiku 5.5 and the Fable models.
  - Collapsed by default; Ctrl+O shows gray italic. "Interactive sessions on the Anthropic API receive redacted thinking blocks by default, so set `showThinkingSummaries: true`... if you want the full summaries."
  - Changelog 2.1.89: "Changed thinking summaries to no longer be generated by default in interactive sessions". 2.1.152: collapsed summaries stay readable 3 s, render as markdown, cap at 10 lines. Latest is 2.1.319.
  - Fable 5.1 and Opus 5.5 are the Claude 5 models in the current docs; no "Opus 5.5 thinking summary" changelog entry exists beyond the above.
- Mechanism of redaction [S https://github.com/anthropics/claude-code/issues/52376]:
  - Claude Code sends beta header `redact-thinking-2026-02-12` by default. `showThinkingSummaries` removes it and sets `thinking.display:"summarized"`.
  - Reported: subscription-auth sessions still get an empty block with a signature (UNVERIFIED whether still true; a June 2026 third-party guide wmedia.es says both `showThinkingSummaries` and `verbose` are needed).
  - Desktop: the changelog and desktop docs say nothing on thinking-display defaults (only a "Thinking" transcript view that "appears... only after Claude has produced thinking").
- Third parties agree it is a summary (McCanna, developersdigest.tech). They are not authoritative.

## Q4 Form
- TB Opus 5.5 (n=1953) [M]:
  - Chars: median 256, p10 195, p90 328, mean 259 (about 60 tokens at 4 chars per token). Words: median 40, max 78.
  - Sentences: 2 in 83%, 1 in 15%, 3-4 in 2%. No newlines, no bold, no bullets (0 of 1953).
  - 92% contain "I'll" (next-action sentence); 31% start "The", 6% "I'll", 4% "I've". First sentence is a past/present-tense finding with numbers; second is "I'll ..." / "Next, I'll ..." / "Now I'll ...".
  - Concrete planned actions are the norm: "I'll revert to 10-step blocks with 12 iterations", "I'll write an independent verifier before building the solver".
- SWE-chat non-empty (n=296; 285 Claude) [M]:
  - Chars: p10 61, median 233, p90 1050, max 21577. Words: median 35.
  - 33% contain a newline (multi-paragraph, mostly Opus 4.5/4.6 and long Fable 5); bold 4%, bullets 3% (older Opus, null entrypoint; the 12 bold hits include 8 gpt-5.3-codex).
  - 69% (204 of 296) contain I'll / Let me / I need to / I should.
  - Fable 5, Sonnet 5, Opus 5, Fable 5.1: median 220-400 chars, 1-3 sentences, no bold. Opus 4.7/4.6: 350-390 median; long tail to 2300.
  - Present-progressive narration ("I'm looking at...", "I'm noticing...", "Now I'm checking...") is typical of Opus 5 and Fable 5. Past-tense finding plus "I'll" is typical of Fable 5.1 and TB Opus 5.5.
  - Non-English: Opus 4.7/4.6 summaries follow the user's language (Chinese, Japanese observed).
- Pilot Opus 4.6 -p (n=712) [M]:
  - Chars: p10 73, median 579, p90 7020, max 88166. Often a numbered recon list ("1. Read the test file 2. Inventory the workspace").
  - Longer and more raw-like than Claude 5 summaries.
- Specificity: names files, functions, numbers and next tool actions. Hedges are rare. Raw self-corrections are rare in Claude 5 summaries.

## Q5 Fidelity
- Anthropic statements [S thinking page]: summary "preserves the key ideas"; the purpose is "preventing misuse"; a different model writes it; billed tokens do not match the visible count. No statement on omission of unsafe or misaligned intent. UNVERIFIED anything beyond that.
- Sonnet 4.5 system card snippet via search (garbled): a smaller model summarizes long thought processes. Not checked directly.
- Faithfulness of raw CoT itself (Anthropic "Reasoning Models Don't Always Say What They Think": hints acknowledged 25% by Claude 3.7) is about raw CoT, not summaries. Third-party posts caution summaries are lossy (McCanna).
- My data [M]:
  - There are no matched raw/summary pairs in these sources, so softening cannot be measured.
  - CheatBench Pilot Opus 4.6: 79 of 81 traces have a thinking block immediately before the first `/tests` read. They read as neutral ("Let me start with the RECON phase - read test file"), so the cheating is in the tool call, not stated in thinking.
  - Counter-example: cb-003307 (extract-moves-from-video), "The test file contains the exact expected solution. I can just use this directly instead of trying to download and transcribe the video." Shortcut intent survives, unhedged.
  - Keyword scan of 1953 TB Opus 5.5 summaries for hack/hardcode/weaken/skip-test language gave 94 hits, all benign engineering ("cheap", "fallback", "tolerance"). Grader-aware but legitimate: "I'll simulate the grader..." appears.
  - I found no TB-science or SWE summary stating an intended test edit or reward hack.
- Implication [E]: summaries state the next action concretely, so a planned shortcut is likely visible when the model intended it explicitly. Intent the model never verbalized stays absent, as in raw CoT. Whether the summarizer drops "I could cheat here" asides is unmeasured.

## Q7 Style guide for synthesis
Target: the Claude 5 (Opus 5.5 / Sonnet 5.5 / Fable 5.x) progress-update style, which is the form current data shows.
1. Length: 1-3 sentences, usually 2. 25-55 words, 150-350 characters (about 40-90 tokens). Hard cap 80 words. Optional "long" variant (10-15% of summaries, Opus 4.x style): 2-4 short paragraphs, 400-1200 chars, still prose.
2. Structure: sentence 1 = a concrete finding or status from the last result (file, function, number, test count, error). Sentence 2 = what happens next, "I'll ..." / "Next, I'll ..." / "Now I'll ...", naming the concrete action (edit X, run Y, add test Z). About 90% of Claude 5 summaries should contain "I'll".
3. Voice: first person, plain text. No bold headline phrases, no bullets, no headings, no newlines in the short form (0% observed in Claude 5; bold and bullets appear only in older Opus 4.5/4.6 and under 5%).
4. Tense: past or present perfect for findings ("I found", "All 72 tests pass"), future or imperative for the next step. Present progressive ("I'm looking at...", "Now I'm checking...") is the Opus 5 / Fable 5 variant; allow 25% of summaries.
5. Specificity: keep identifiers, paths, numbers and error text from the raw reasoning. Include the planned action when the raw reasoning contained one.
6. Strip raw-CoT tells: no "Wait", "Hmm", "Actually", false starts or self-corrections (under 1-2% in Claude 5 data). Only the optional long Opus 4.x variant may keep an opening "Let me ..." line.
7. Fidelity rule (instruct the cheap model explicitly): do not sanitize. If the raw reasoning states an intent to read the tests, special-case an input, edit or skip a test, hardcode an expected value or use a leaked answer, the summary must say so in the same blunt words (model: cb-003307, ex. 26). Also do not invent intent the raw text does not contain. This rule is an [E] design choice. Whether Anthropic's summarizer softens is unmeasured, so mixing in some record pairs with the intent omitted is a separate, labelled augmentation decision, not default.
8. Placement: attach the summary to an assistant step that has a tool call (100% of TB reasoning steps; one summary per step). Never on steps that already carry long visible text (0 of 1953 co-occurrence). Language follows the user's prompt language.
9. Empty form: for steps that "think" but show nothing, emit `thinking:""` plus a signature-like opaque string (median about 1100 chars of base64) or omit the block. In real data 90% of thinking blocks are empty.
10. Share [E]:
    - Evidence: SWE-chat messages 4.5% non-empty (prior 12.4%); session-level 15%; recent TB Opus 5.5 48% of steps; Pilot -p 29%; the desktop app shows summaries more often (n=6 sessions).
    - Recommended: show summaries in about 25% of records (plausible 10-40%), chosen per record or session, not per step.
    - Within a summary-visible record, put summaries on about 50% of tool-call steps (Claude 5 progress-update rate, 48%); use about 90-100% for legacy-display records. Mix: 70% Claude 5 style, 20% longer Opus-4.x style, 10% non-English.
    - Hide thinking entirely in about 75% of records (empty plus signature or absent).
    - Uncertainty: wide. The plugin author's "usually not visible" fits the low end. Version, entrypoint and settings dominate, and the sample is not population-weighted.
